# الإعداد الأول

يقلع المشروع بلا مفتاح OpenRouter وبلا ويبهوك ديسكورد — اللوحة تعمل، والتسليم وحده
يتأثر. هذا الدليل لملء الفراغين، ولربط GitHub.

للنشر على خادم: [DEPLOY.md](DEPLOY.md).

---

## ١. التشغيل

```bash
cp .env.example .env
npm run up
```

اللوحة على `http://localhost:8080`. الهجرات تعمل عند إقلاع الـAPI.

الأسرار تُولَّد بـ`openssl rand -hex 32`. والمولَّد لك مسبقاً في `.env.example`:

| المتغيّر | ما هو |
|---|---|
| `POSTGRES_PASSWORD` / `DATABASE_URL` | عشوائي؛ القاعدة لا تُنشر على مضيفك أبداً |
| `SESSION_SECRET` | يوقّع كوكي الجلسة. تدويره يخرج الجميع |
| `GITHUB_WEBHOOK_SECRET` | نفس القيمة تُلصق في حقل **Secret** عند GitHub |
| `DASHBOARD_PASSWORD` | دخولك للوحة. غيّرها |

## ٢. `OPENROUTER_API_KEY`

النموذج الذي يكتب البلاغ. بدونه ينزل كل تقرير إلى جملة واحدة، وتُظهر صفحة البرقيات
`llm_failed`.

1. سجّل الدخول في **https://openrouter.ai**.
2. **https://openrouter.ai/keys** ← **Create Key**.
3. انسخه فوراً — يُعرض مرّة واحدة. يبدأ بـ`sk-or-v1-`.
4. ضعه في `OPENROUTER_API_KEY`.

النماذج المجانية لا تحتاج فوترة، لكن OpenRouter يطلب رصيداً في الحساب لبعضها **ويسحب
معرّفات المجانية بلا إشعار**. القائمة الحالية: **https://openrouter.ai/models?max_price=0**
— ضع أي معرّف في `OPENROUTER_MODEL`.

---

## ٣. `DISCORD_WEBHOOK_URL`

القناة التي تصلها البلاغات. هذه القناة **الاحتياطية**؛ يمكن تركها فارغة وتحديد رابط
لكل جبهة من اللوحة.

1. في ديسكورد: القناة ← **Edit Channel** (الترس).
2. **Integrations** ← **Webhooks** ← **New Webhook**.
3. سمّه، اختر القناة، ثم **Copy Webhook URL**.
4. ضعه في `DISCORD_WEBHOOK_URL`. شكله `https://discord.com/api/webhooks/<id>/<token>`.

يحتاج إنشاؤه صلاحية **Manage Webhooks** على السيرفر.

## ٤. أسبقية الإعدادات — تُقرأ مرّة

`OPENROUTER_MODEL` و`DEFAULT_LOCALE` وأخواتهما في `.env` **بذور إقلاع أولى فقط**. عند
أول تشغيل يزرع الـAPI صفّ الإعدادات منها، ومن تلك اللحظة **القاعدة هي المرجع واللوحة
هي طريق التغيير**.

تعديل `.env` وإعادة التشغيل **لن يغيّرا النموذج**. غيّره من صفحة الإعدادات، أو:

```bash
curl -b cookie.txt -X PATCH http://localhost:8080/api/settings \
  -H 'Content-Type: application/json' -d '{"model":"<model-id>"}'
```

والأسرار عكس ذلك تماماً (`DASHBOARD_PASSWORD`، `SESSION_SECRET`،
`GITHUB_WEBHOOK_SECRET`، المفاتيح): تُقرأ من البيئة عند كل طلب ولا تُخزَّن أبداً — فهذه
**تحتاج** تعديل `.env` وإعادة تشغيل.

## ٥. ويبهوك GitHub

GitHub لا يصل حاوية على جهازك. عرّض المنفذ أولاً ([DEPLOY.md](DEPLOY.md))، وضع
`PUBLIC_URL` على العنوان العام — اللوحة تبني منه رابط الويبهوك، وهو أصل CORS في الإنتاج.

ثم في الريبو: **Settings ← Webhooks ← Add webhook**

| الحقل | القيمة |
|---|---|
| Payload URL | `<PUBLIC_URL>/api/webhook` |
| Content type | `application/json` |
| Secret | نفس `GITHUB_WEBHOOK_SECRET` |
| Events | Just the push event |

> **quick tunnel (`trycloudflare.com`) لا يكفي** — رابطه يتغيّر كل تشغيل فينكسر الويبهوك.

## ٦. GitHub App — اختياري، للإثراء

حمولة الدفعة تحمل رسائل الكوميت والمسارات، **لا عدد الأسطر ولا محتوى الملفات**. تثبيت
App هو ما يحوّلها إلى ثلاث ميزات:

| الميزة | لماذا تحتاج الـApp |
|---|---|
| الأسطر المضافة/المحذوفة لكل كوميت | الحمولة مسارات بلا إحصاءات فرق |
| من لمس أي ملف آخر مرّة | يُبنى من قوائم ملفات الكوميتات، واحداً واحداً |
| اقتباس وثيقة قواعد المشروع المراقَب | الملفّ الشخصي يقرأ `CONSTITUTION.md` / `CONTRIBUTING.md` من الفرع الافتراضي |
| **استرجاع ما فات أثناء الانقطاع** | المصالحة تسحب الكوميتات الأحدث من آخر مسجَّل |

وبدونها يظلّ الملفّ الشخصي يعمل — **يصرّح بأن البيانات غير متاحة بدل أن يخترعها**.

1. **https://github.com/settings/apps** ← **New GitHub App**. للمؤسّسات:
   `https://github.com/organizations/<org>/settings/apps`.
2. سمّه، ضع أي Homepage، و**ألغِ تفعيل Webhook → Active** — هذا التطبيق للقراءة فقط،
   وويبهوك الدفع يُضبط منفصلاً.
3. **Permissions ← Repository permissions**: `Contents` → **Read-only**، و`Metadata` →
   **Read-only**. لا شيء غيرهما.
4. أنشئه. **App ID** أعلى صفحة الإعدادات ← `GITHUB_APP_ID`.
5. نفس الصفحة، **Private keys ← Generate a private key**. ينزل `.pem` مرّة واحدة ←
   `GITHUB_APP_PRIVATE_KEY`.
6. **Install App** ← ثبّته على الجبهات التي تراقبها.
7. افتح صفحة التثبيت؛ الرابط ينتهي بمعرّفه:
   `https://github.com/settings/installations/12345678` ← `12345678`.
8. ضع الرقم في حقل **معرّف تثبيت GitHub App** الخاص بالجبهة في اللوحة. **لكل جبهة على
   حدة** لا عالمياً — تطبيق واحد يخدم عدّة جبهات، لكلٍّ تثبيتها.

### صيغة المفتاح — الخطأ الذي يكلّف ساعة

`.pem` متعدّد الأسطر و`.env` ليس كذلك، فيقبل `GITHUB_APP_PRIVATE_KEY` صيغتين:

```bash
awk 'BEGIN{ORS="\\n"} {print}' app.private-key.pem   # سطر واحد بـ \n حرفية
base64 -i app.private-key.pem | tr -d '\n'           # أو base64 للملف كاملاً
```

**المطلوب الملفّ بكامله** بما فيه سطرا BEGIN وEND. ترميز جسم المفتاح وحده يُنتج
`DECODER routines::unsupported` — **عند أول استعمال لا عند الإقلاع**، فتظنّ الإعداد سليماً.

وانتبه: **App ID غير Installation ID.** الأول رقم صغير في صفحة إعدادات التطبيق، والثاني
كبير في رابط التثبيت. خلطهما يعطي `404 Integration not found`.

أعد تشغيل الـAPI بعد ضبطهما. الإثراء يعمل في دورة الصيانة الساعية، فـ`enriched` تنقلب
خلال ساعة لا فوراً.

## حدود معروفة

مقايضات مقبولة، مكتوبة حتى لا يُعاد اكتشافها.

| الحدّ | الأثر |
|---|---|
| GitHub يقصّ `commits` عند ٢٠ لكل دفعة | العدّادات تنقص في الدفعات الكبيرة — والتقرير يصرّح بأن الحمولة قُصّت |
| حقن البرومبت مُخفَّف لا محلول | الحارس يرفع الكلفة؛ زميلٌ مصمّم وله صلاحية دفع يظلّ قادراً على التأثير |
| إزاحة UTC ثابتة، بلا توقيت صيفي | قواعد الليل ونهاية الأسبوع تنزاح ساعة في المناطق التي تطبّقه |
| النماذج المجانية تُسحب بلا إشعار | التقرير يسقط إلى جملة واحدة، ظاهرةً كـ`llm_failed` |
| اللوحة بكلمة واحدة، بلا حسابات | من يملكها يملك كل شيء |
| العامل داخل عملية الـAPI | مقبول عند هذا الحجم. فصله لاحقاً لا يحتاج تغيير كود — المطالبة بـ`FOR UPDATE SKIP LOCKED` |
| بنية الكود تُقاس لـTypeScript/JavaScript وحدها | لغات أخرى تُقاس بعدد الأسطر فقط. [مقترح 0006](proposals/0006-language-parsers.md) |
