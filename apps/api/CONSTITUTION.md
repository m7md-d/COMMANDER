# دستور الباك إند

فرعي عن [الدستور العام](../../CONSTITUTION.md). ما يُذكر هناك لا يُعاد هنا.

---

## ١. خريطة المجلدات

| المجلد | مسؤوليته | ممنوع فيه |
|---|---|---|
| `config/` | متغيرات البيئة والثوابت | أي منطق عمل |
| `core/` | أدوات عامة: أخطاء، ردود، تسجيل، تشفير | معرفة بأي module |
| `db/` | عميل Prisma وحده | استعلامات |
| `middleware/` | ما يعترض الطلب قبل الـ controller | منطق عمل |
| `domain/` | قواعد ومنطق نقي | Express، Prisma، fetch، Date.now بلا تمرير |
| `integrations/` | كل ما يخرج للشبكة | قرارات عمل |
| `modules/` | الميزات: service + controller + routes | استعلام داخل controller |
| `queue/` | الطابور والمعالج | تعريف قواعد جديدة |

**اتجاه الاعتماد المسموح:**
`modules → domain, integrations, core, db` — والعكس ممنوع.
`domain` لا يستورد شيئاً خارج `domain` و`@commander/shared`.

---

## ٢. تشريح الـ module

كل module ثلاثة ملفات على الأقل، بأدوار لا تتداخل:

| الملف | يفعل | لا يفعل |
|---|---|---|
| `*.routes.ts` | يربط المسار بـ validate ثم controller | يحتوي منطق |
| `*.controller.ts` | يقرأ المُتحقق منه، ينادي service، يرد | يستعلم، يتحقق يدوياً، يمسك أخطاء |
| `*.service.ts` | منطق العمل والوصول لـ Prisma | يعرف `req`/`res` |
| `*.mapper.ts` | يحوّل صف Prisma إلى DTO | منطق عمل |

**قاعدة:** الـ controller ينادي **service واحداً**. لو احتاج اثنين، المنطق مكانه في service ثالث.

## ٣. الطلب — من الاستقبال إلى الرد

```
helmet
  └─ /api/webhook  ← قبل express.json عمداً (البايتات الخام لازمة للتوقيع)
  └─ express.json → cookieParser → [cors في التطوير]
       └─ /api/auth            عام
       └─ /api/*  requireSession
            └─ validate(schema) → controller → service → domain/prisma
                 └─ خطأ → next() → errorHandler → { ok:false, error:<key> }
```

مقارنة بالنسخة القديمة على Cloudflare Worker: كانت المعالجة داخل `ctx.waitUntil`
بعد الرد، فأي فشل يختفي ولا يُعاد. الآن الويبهوك يكتب صفاً في `deliveries` ويرد
202، والـ worker يسحب ويعيد المحاولة — والفشل مرئي في اللوحة.

## ٤. قواعد الطابور

| القاعدة | لماذا |
|---|---|
| `processDelivery` لا يرمي أبداً | الرمي يترك الصف عالقاً في `processing` |
| كل مسار خروج يكتب حالة نهائية | صف بلا حالة = تقرير ضائع بصمت |
| المطالبة بالصفوف بـ `FOR UPDATE SKIP LOCKED` | يسمح بتشغيل أكثر من نسخة API بلا ازدواج |
| المعالجة تسلسلية داخل الدفعة | التوازي على نموذج مجاني يحوّل طابورنا إلى 429 عندهم |
| `retryable` يقرره التكامل لا المعالج | العميل وحده يعرف هل 404 نهائي و503 مؤقت |
| احترم `retry_after` من ديسكورد | تجاهله يوصل لحظر الويبهوك |

**أسباب لا تُعاد المحاولة لها:** كل ما في `NON_RETRYABLE_REASONS` — إعادة المحاولة
لا تغيّر النتيجة، فهي إهلاك حصة بلا فائدة.

## ٥. إضافة قاعدة مخالفة

خمس خطوات، ولا شيء غيرها:

1. `RULE_IDS` و`RuleConfigMap` و`defaultRuleConfig()` في `@commander/shared`
2. ملف `domain/violations/rules/<name>.rule.ts` — دالة نقية واحدة
3. سطر في `domain/violations/registry.ts`
4. سطر في `overlay()` داخل `engine.ts`
5. ثلاثة مفاتيح i18n: `rule.<id>.label` / `.hint` / `.report`

نسيان أي من ٣ أو ٤ = خطأ ترجمة، مو خطأ وقت تشغيل. هذا مقصود.

## ٦. Prisma

| القاعدة | لماذا |
|---|---|
| `schema.prisma` أولاً، ثم `prisma migrate dev --name <وصف>` | الـ migration جزء من الـ commit لا خطوة لاحقة |
| ممنوع `prisma db push` خارج التجريب المحلي | يتخطى تاريخ الهجرات |
| ممنوع تصدير نوع Prisma خارج `modules/` | mapper يحوّله لـ DTO أولاً |
| JSON للأشكال المتغيّرة فقط (`rules`, `settings`, `payload`) | وكلها تمر بـ zod عند القراءة |
| `select`/`include` صريح في الاستعلامات الواسعة | يمنع تسريب أعمدة لم نقصدها |

---

## ٧. الاختبارات

- `domain/` يُختبر بلا قاعدة بيانات وبلا خادم — هذا سبب وجوده منفصلاً.
- كل قاعدة مخالفة تحتاج حالتين على الأقل: تشتعل، ولا تشتعل في الحالة المخادعة
  (مثال إلزامي: PR مدموج بـ squash **لا** يُحسب `direct_push`).
- الأمان يُختبر: توقيع خاطئ يُرفض، وسر لا يظهر في أي رد.
