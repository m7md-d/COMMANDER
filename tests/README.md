# مجلد الاختبارات

هذا المجلد ليس اختبارات وحدة. اختبارات الوحدة تعيش **بجانب الكود الذي تختبره**
(`*.test.ts` داخل `src/`)، لأن دالة واختبارها يُقرآن ويُعدَّلان معاً، وفصلهما
يجعل تعديل السلوك يمسّ مجلدين.

ما هنا مختلف: **حراس عابرون للمشروع كله**. لا يفحصون ماذا تفعل دالة، بل ما لا
يستطيع أي اختبار وحدة رؤيته — أن الدستور لا يزال مطبَّقاً، وأن لا شيء بقي بلا
فائدة، وأن الصفحة لم تثقل والاستجابة لم تبطؤ.

## التشغيل

```bash
npm run test:guards      # الحراس وحدهم
npm run test             # اختبارات الوحدة + الحراس
npm run verify           # typecheck + lint + build + test  ← قبل ادّعاء الإنجاز
```

`verify` يبني قبل الاختبار عمداً: ميزانية حجم الصفحة تُقاس على المخرجات
المبنيّة، وحارس لا يجد ما يقيسه لا يجوز أن يمرّ صامتاً.

## التقسيم

| المجلد | يجيب على |
|---|---|
| `lib/` | ما الذي يُعدّ ملفاً خاضعاً للقواعد؟ وما هي الأرقام؟ **كل رقم في المشروع هنا** |
| `constitution/` | هل الدستور لا يزال مطبَّقاً؟ |
| `coverage/` | هل بقي شيء بلا فائدة، أو نقص شيء مطلوب؟ |
| `budgets/` | هل التجربة لا تزال سلسة؟ |

### `lib/` — القاعدة المشتركة

`sources.ts` يمشي على الريبو مرة واحدة ويقرّر ما الذي يُفحص. لو أجاب كل حارس عن
هذا السؤال بنفسه، لاختلف الحرّاس تدريجياً حول الريبو الذي يحرسونه.

`budgets.ts` يجمع **كل حدّ رقمي**: أطوال الملفات، أوزان الحزم، أزمنة الاستجابة.
الحدود المبعثرة يرفعها من يتضايق منها واحداً واحداً ولا يرى أحد الاتجاه؛ هنا رفع
أي حدّ = فرق على ملف واحد، يُراجَع ويُبرَّر كما يفرض الدستور §٩.

`codeOnly` و`commentsOnly` وجهان لمسح واحد: الأول يطمس التعليقات، والثاني يطمس ما
عداها، وكلاهما يحفظ الأطوال فيبقى رقم السطر في رسالة الفشل صحيحاً. والمسح **ماسح لا
تعبير نمطي**، لأن `"src/*.ts"` لا يفتح تعليقاً — ونمطٌ يظنّ ذلك يبتلع كل شيء حتى
`*/` التالية. كان ذلك إنذاراً كاذباً حقيقياً، لا احتمالاً نظرياً.

### `constitution/` — ما لا يمسكه المترجم

| الملف | البند |
|---|---|
| `size.test.ts` | §٤ — ٢٠٠ سطر للملف، ١٥٠ لمكوّن React |
| `layering.test.ts` | §٢ و§٥.١ ودستور الفرونت §١ و§٨ — اتجاه الاعتماد |
| `purity.test.ts` | §٢ و§٣ و§٦ — لا `any`، لا ابتلاع خطأ، لا نص مرئي في الكود |
| `identity.test.ts` | دستور الفرونت §٢ و§٣ — التوكنز والاتجاه المنطقي |
| `naming.test.ts` | §٥ — الاصطلاحات، **وهي ليست زينة**: الحرّاس أعلاه يجدون ضحاياهم بلاحقة الدور |

### `coverage/` — لا شيء بلا فائدة، ولا ناقص

| الملف | يرصد |
|---|---|
| `dead-code.test.ts` | ملف لا يستورده أحد · صنف CSS لا يُستعمل · **اعتمادية معلنة ولا تُستورد** |
| `i18n.test.ts` | تطابق القاموسين · مفتاح بلا قارئ · **مفتاح يطلبه الكود ولا وجود له** |
| `references.test.ts` | مسار وثيقة أو ملف يشير إليه الريبو ولا وجود له |
| `domain-tests.test.ts` | دالة مُصدَّرة من `domain/` لا يسمّيها اختبار |
| `proposals.test.ts` | حالة مقترح غير معرَّفة، أو فهرسٌ يخالف الملف |
| `tooling.test.ts` | سكربت npm يكتب محرّك حاويات حرفياً بدل `scripts/compose.sh` |
| `tracked.test.ts` | ملفّ مصدر يتجاهله git — أي لن يوجد في نسخة جديدة |

`tracked.test.ts` مكتوب من عطل وقع فعلاً: `.gitignore` فيها `coverage/` مقصودةً لمخرجات
أداة تغطية، وgit يطابق الاسم **في أي عمق** — فابتلعت `tests/coverage/` بكاملها، ثمانية
حرّاس. ولم يفشل شيء: الحرّاس يقرأون من نظام الملفات فظلّوا يمرّون هنا، ونسخةٌ جديدة كانت
ستحمل حرّاساً أقلّ ممّا يدّعيه الريدمي بلا أن ينتبه أحد.

**ونفس العطل كان في `sources.ts`**: `coverage` في قائمة أسماء التخطّي، فلم يكن أي حارس
يرى مجلد `tests/coverage/` أصلاً — لا حدّ الحجم ولا التسمية ولا فحص المراجع. الاسم غير
المثبَّت يطابق أكثر ممّا يقصد، والاثنان مثبَّتان الآن بالمسار.

والحارس ينادي `git check-ignore` ولا يقرأ `.gitignore` بنفسه: القواعد تتركّب من ملف
الريبو والملفات المتداخلة و`.git/info/exclude` والتجاهل العام للمستخدم، وإعادة تنفيذ ذلك
هي الطريق إلى حارسٍ يخالف الأداة التي يحرسها.

`domain-tests.test.ts` هو أتمتة القاعدة «الاختبار يتغيّر مع السلوك في نفس التعديل».
و`domain/` أولى الطبقات بها: لا I/O ولا قاعدة بيانات، فلا عذر متاح — وإن كان الحكم
فيها خاطئاً فلا يكتشفه إلا اختبار، والتقرير في الأثناء مخطئ في حقّ شخص حقيقي.

يسأل عن **التسمية** لا عن نسبة تغطية: اختبارٌ لا يذكر الدالة لا يختبرها، ونسبةُ تغطية
تُرضيها اختباراتٌ لا تؤكّد شيئاً. ويقرأ **المعرّفات وحدها** (`symbolsOnly`) لأن عناوين
الاختبارات نثر — عنوان فيه كلمة `credit` كان يجعل `credit()` تبدو مختبَرة.

ومعه قائمة `UNTESTED_AT_ADOPTION`: ٣١ دالة تسبق القاعدة، مؤرَّخة ٢٠٢٦-٠٨-٠٣. سُجّلت
حتى تبدأ القاعدة على الشغل الجديد فوراً بدل انتظار يومٍ لن يُجدوِله أحد. **والقائمة
تنقص ولا تزيد:** اسمٌ صار مختبَراً، أو لم يعد موجوداً، يُفشل الحارس أيضاً — استثناءٌ
لم يحذفه أحد ادّعاءٌ عن الكود توقّف عن الصدق.

`references.test.ts` يوجد لأن الحرّاس أنفسهم يستشهدون بالبند: رسالة فشل تقول
`docs/CHECKS-ROADMAP.md §3` تعني أن السبب مكتوب هناك. فمسار الوثيقة جزء من العقد،
ووثيقةٌ تُنقَل تحوّل كل استشهاد بها إلى طريق مسدود لا يلاحظه شيء آخر: الكود يُترجم،
والاختبارات تمرّ، والقارئ يُرسَل إلى العدم.

في `apps/` و`packages/` يقرأ **التعليقات وحدها**: المسار في تعليق استشهاد، ونفسه في
مصفوفة بيانات — `CONSTITUTION_CANDIDATES` تصف ملفات في ريبو المستخدم يُفترض ألّا
توجد عندنا. والحرّاس تحت `tests/` يحملون استشهاداتهم في رسائل الفشل لا في التعليقات،
فيُقرأون كاملين. والمراسي (`#section`) لا تُفحص عمداً: قواعد اشتقاقها تختلف بين
العارضات ومعظم عناويننا عربية، وحارسٌ يخالف GitHub في اشتقاق مرساة يُطلق على روابط
صحيحة.

الأخير أمسك عيباً حياً: مخططات zod كانت تُصدر `repo.branchEmpty` والقاموس يعرّف
`repos.branchEmpty` — فرسائل التحقق كانت تُعرض للمستخدم كمفتاح خام.

### `budgets/` — التجربة

| الملف | يقيس |
|---|---|
| `bundle.test.ts` | وزن كل قطعة مضغوطة + المجموع + بقاء الفصل بين كودنا والاعتماديات |
| `response.test.ts` | زمن الاستجابة الوسيط مقابل مكدّس شغّال |

`response.test.ts` **يتخطّى** حين لا يوجد خادم، ويقول ذلك بصوت عالٍ. فحص زمن
يحتاج بنية تحتية يجب ألّا يحوّل `verify` إلى شيء ينجح على جهاز واحد. لضبط
العنوان: `PANEL_URL=https://… npm run test:guards`.

## إضافة حارس

١. الرقم — إن كان فيه رقم — يذهب إلى `lib/budgets.ts`، لا داخل الاختبار.
٢. الاختبار يجمع **كل** المخالفات ثم يفشل مرة واحدة بقائمة. الفشل على أول مخالفة
   يعني إصلاحاً بطيئاً على جولات.
٣. رسالة الفشل تقول **ماذا يُفعل**، لا ماذا حدث فقط.
٤. الاستثناء يُكتب كنمط مسمّى مع سبب. استثناء بلا سبب مكتوب يُحذف لاحقاً بلا نقاش
   (الدستور §٩).
٥. صفر إنذارات كاذبة. حارس يُطلق على شغل سليم يُطفأ — وحارس مُطفأ أسوأ من غيابه.
